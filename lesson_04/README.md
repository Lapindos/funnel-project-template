# Задание 4 · Свои события и параметры в GA4

По презентации **Тема 06 · События и параметры GA4** на сайте курса.
Работа сдаётся скриншотами из своего ресурса GA4 и кодом своего сайта.

В теме 6 вы добавляли на сайт два обработчика — `generate_lead` и
`cta_click` — и смотрели их в DebugView. Здесь нужно добавить ещё четыре
метрики по готовым скриптам и показать, что они доходят до аналитики.

## Какие метрики добавить

| Событие | Что измеряет |
|---|---|
| `nav_click` | по каким пунктам меню ходят посетители |
| `utm_visit` | метки кампании из адреса страницы |
| `read_30s` | посетитель остался на странице полминуты |
| `form_error` | браузер не пропустил отправку формы |

Код каждой метрики есть в презентации на слайдах практики: кнопка
**«Копировать файл»** и отдельные блоки с кодом. Всё четыре куска одним
файлом лежат в [материалах темы 6](https://algorthimization-course-vvodnoe.vercel.app/op03-informacionnye-tehnologii/lessons/06-ga4-events/materials.html)
— файл `js/metrics.js`.

Придумывать свои события не нужно: берите готовые скрипты, кладите файл
в папку `js/` своего сайта и подключайте на всех страницах после
основного скрипта:

```html
<script src="js/script.js" defer></script>
<script src="js/metrics.js" defer></script>
```

После этого опубликуйте изменения обычным путём: commit → push →
Deployment в статусе **Ready**.

## Что нужно доказать скриншотами

| № | Что доказываем | Где это видно |
|---|---|---|
| 1 | Метрики добавлены в ваш проект | редактор: файл `js/metrics.js` и строка подключения в HTML |
| 2 | События доходят до аналитики | **DebugView**: в ленте видны ваши новые события |
| 3 | Параметры приходят вместе с событием | раскрытое `utm_visit`: значения `utm_source`, `utm_medium`, `utm_campaign` |
| 4 | Событие видно не только в отладке | **Realtime** сразу после действия, либо отчёт **Отчёты → Взаимодействие → События** на следующий день |

Сайтом служит ваша копия шаблона
[ga4-analytics-lab](https://github.com/MaximBytecamp/ga4-analytics-lab),
опубликованная на Vercel, и ваш ресурс GA4 из задания 3.

## Что появится сразу, а что на следующий день

DebugView и Realtime показывают событие через несколько секунд. Раздел
«События» и карточки разрезов в отчётах наполняются после обработки
данных — обычно в течение суток. Поэтому четвёртый кадр снимайте либо
в Realtime сразу, либо в отчёте на следующий день: пустой отчёт в день
настройки — это не ошибка.

## Ссылка для проверки меток

Метки читает событие `utm_visit`, поэтому сайт нужно открыть по размеченной
ссылке — подставьте свой адрес:

```text
https://ВАШ-ПРОЕКТ.vercel.app/?utm_source=telegram&utm_medium=social&utm_campaign=ga4_lab
```

Открывайте её в новом окне браузера: переход по ссылке внутри той же
вкладки метки не обновит.

## Как оценивается

| Что проверяется | Вес |
|---|---|
| Четыре метрики добавлены и опубликованы (кадр 1) | 25% |
| События видны в DebugView (кадр 2) | 25% |
| У `utm_visit` пришли значения меток (кадр 3) | 25% |
| Событие видно в Realtime или в отчёте (кадр 4) | 15% |
| Бланк заполнен, адреса и идентификаторы совпадают с кадрами | 10% |

Кадры из чужого ресурса и демонстрационные не принимаются: по Measurement ID
сверяется, что аналитика ваша.

## Если события не появляются

| Признак | Что проверить |
|---|---|
| В DebugView пусто | подключение через Tag Assistant не закрыто, сайт открыт по публичному адресу |
| Нет ни одного нового события | файл `js/metrics.js` лежит в `js/` и подключён на странице, Deployment в статусе Ready |
| `nav_click` не приходит | событие уходит при переходе на другую страницу, ищите его в конце ленты предыдущей страницы |
| `read_30s` не приходит | на странице нужно пробыть полминуты, не сворачивая вкладку |
| `utm_visit` не приходит | сайт открыт без меток: нужна ссылка с `utm_source` |
| `form_error` не приходит | форму отправляют с пустыми обязательными полями |
| В отчёте пусто | за период данные появляются не сразу, в Realtime — сразу |
